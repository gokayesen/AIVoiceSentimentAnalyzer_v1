# Story 1.4: Transcript Generation (STT)

Status: done

<!-- Note: Validation is optional. Run validate-create-story for quality check before dev-story. -->

## Story

As an Analyst,
I want the Call's audio transcribed,
so that I have a text record and text-based analysis has input to work from.

## Acceptance Criteria

1. **Given** a Call has completed ingest, **when** the transcript-generation filter runs, **then** it produces a text transcript of the English-language audio via faster-whisper, running entirely locally (AD-5, FR-6). [Source: epics.md#Story 1.4: Transcript Generation (STT); AD-5, FR-6]
2. **Given** transcript generation runs, **when** it produces its output, **then** every `TranscriptTurn` carries word-level timestamps (AD-5). [Source: epics.md#Story 1.4; AD-5]
3. **Given** this stage is implemented, **then** no alternate STT engine may be substituted without amending the Architecture spine — faster-whisper is the sole permitted engine for this stage (AD-5). [Source: epics.md#Story 1.4; AD-5]
4. **Given** the transcript-generation filter fails, **when** this occurs, **then** the Call's transcript path is marked failed for this Call, but this does not fail the Call overall — the acoustic signal (Story 1.3) remains valid and usable independently, and `Call.status` must never be set to `"failed"` because of a transcript-stage failure (AD-1). [Source: epics.md#Story 1.4; AD-1]
5. **Given** a `TranscriptTurn` is produced, **then** it relates to `TimelineSegment`s only via time-range overlap — never via a scalar `segment_id` foreign-key column on `TranscriptTurn` (AD-11: "each `TranscriptTurn` is associated with every `TimelineSegment` whose time range overlaps it — a many-to-many relationship... not a single scalar `segment_id` foreign key"). [Source: ARCHITECTURE-SPINE.md#AD-11 Chunking/timeline unification]
6. **Given** transcript generation succeeds (with or without individual-segment transcription gaps), **then** it does not complete the Call — `Call.status` remains `"processing"`; only fusion (Story 1.6) can complete a Call (mirrors Story 1.2 AC5 / Story 1.3 AC9 precedent). [Source: ARCHITECTURE-SPINE.md#AD-1, AD-13]
7. **And** transcript inference runs locally only — no cloud STT API call is made; model weights are fetched once (e.g. at Docker build time), never as a per-Call/per-request network call (AD-14). [Source: ARCHITECTURE-SPINE.md#AD-14]
8. **And** the transcript module has independently-runnable unit tests — `pytest ml-service/` passes with no live Redis/docker-compose (AD-21). [Source: epics.md#Story 1.4; AD-21]

### Review Findings (AI)

- [x] [Review][Defer] Overlapping AD-11 context-margin slices between adjacent `TimelineSegment`s cause duplicate transcribed text/turns in the persisted transcript — the core deliverable of this story. `CONTEXT_MARGIN_SECONDS = 0.5` is applied on both sides of every segment independently in `run.py`. Since `ingest/run.py`'s `_fill_gaps` makes segments contiguous (`segment[i].end_time == segment[i+1].start_time`), any two adjacent segments less than 1.0s apart get overlapping padded windows (e.g. `(0.0,1.5)`→`[0,2.0]` and `(1.5,3.0)`→`[1.0,3.5]`, a 1.0s shared window). Both are transcribed independently with no trimming/deduping back to the segment's own strict range before persisting, so the shared audio's speech is transcribed and persisted twice as separate `TranscriptTurn` rows. AD-11 explicitly forbids clipping `TranscriptTurn` boundaries to force a fit with `TimelineSegment` boundaries, which rules out the simplest fix (trim persisted turns to `[segment.start_time, segment.end_time)`) as a clean, spec-compliant patch — the properly AD-11-aligned fix (transcribing the whole Call once and mapping resulting turns to overlapping segments via time-range overlap, rather than per-segment padded transcription) is a more substantial redesign of Task 5/6. — deferred: out of scope, the real fix requires a redesign (whole-call transcription + AD-11 overlap mapping), not a patch to this story.

- [x] [Review][Patch] `run_acoustic`'s new transcript-queue enqueue call sits inside the same `try` block as the acoustic write, sharing the `except Exception` that rolls back and sets `Call.status = "failed"` [ml-service/app/pipeline/acoustic/run.py] — if `queue.get_transcript_queue().enqueue(...)` itself raises (e.g. Redis unreachable) after `persist_acoustic_results` has already committed valid results, an already-successful acoustic Call gets wrongly marked `"failed"` (rollback is a no-op since the write already committed), producing an inconsistent state (status=`failed` + fully populated acoustic evidence) — contradicts AD-1's "acoustic signal remains independently valid" intent and the atomicity invariant Story 1.3's own review established. — fixed: the enqueue call is now wrapped in its own nested try/except that logs and swallows the failure instead of propagating into the outer except; covered by a new test (`test_run_acoustic_transcript_enqueue_failure_does_not_fail_the_call`).
- [x] [Review][Patch] No `language="en"` pin on `model.transcribe()` [ml-service/app/pipeline/transcript/stt.py] — faster-whisper runs its own per-segment language-detection pass instead of being pinned to English, risking misdetection on short/padded audio slices and violating FR-6/AC1's English-only MVP scope; also costs an unnecessary language-ID pass per segment. — fixed: `language="en"` now passed explicitly; covered by a new test asserting the kwarg is passed through.
- [x] [Review][Patch] No per-segment error isolation in `run_transcript`'s loop [ml-service/app/pipeline/transcript/run.py] — `transcribe_segment` is called with no per-iteration try/except, so one segment's transcription failure (bad data, transient model error) discards every other segment's already-computed turns for the whole Call via the outer blanket except, contradicting the stage's own "best-effort, never fail the whole Call" philosophy (and the zero-width-segment case just above it in the same loop already establishes the skip-and-continue pattern this should follow). — fixed: `transcribe_segment` is now wrapped in a per-segment try/except that logs and continues; covered by a new test.
- [x] [Review][Patch] `condition_on_previous_text` left at faster-whisper's default (`True`) [ml-service/app/pipeline/transcript/stt.py] — a known driver of repeated/runaway hallucination loops when a slice yields multiple internal Whisper segments, undermining the module's own docstring-stated hallucination-mitigation goal. — fixed: now passed as `False`; covered by the same new kwarg-assertion test as the language fix.
- [x] [Review][Patch] `WordResult.word` is not stripped, unlike `TurnResult.text.strip()` [ml-service/app/pipeline/transcript/stt.py] — leading-space artifacts (faster-whisper's convention) leak into persisted `TranscriptWord.word` values with no documented reason for the inconsistency. — fixed: `word.word.strip()` now applied; covered by a new test.
- [x] [Review][Patch] Empty-text `TranscriptTurn` rows can be persisted for filler/non-speech Whisper segments with no filtering [ml-service/app/pipeline/transcript/run.py] — `segment.text.strip()` can yield `""`, and the `text TEXT NOT NULL` schema constraint allows an empty string through. — fixed: whitespace-only segments are now dropped in `transcribe_segment` before turning into a `TurnResult`; covered by a new test.
- [x] [Review][Defer] No idempotency guard against duplicate `TranscriptTurn`/`TranscriptWord` rows if `run_transcript` is retried by RQ [ml-service/app/db.py] — deferred, pre-existing: consistent with the project's existing, twice-already-deferred "no RQ `Retry()` policy exists anywhere in the codebase" precedent (Stories 1.2/1.3 review).
- [x] [Review][Defer] New `TranscriptTurn`/`TranscriptWord` tables have no indexes/unique constraints, and `PRAGMA foreign_keys` remains disabled [ml-service/app/db.py] — deferred, pre-existing: consistent with Story 1.3 review's existing "SQLite `foreign_keys` pragma never enabled" deferral, now also applying to these two new tables.
- [x] [Review][Defer] RQ `Worker`'s fixed `[INGEST, ACOUSTIC, TRANSCRIPT]` priority ordering could starve the transcript queue under sustained upstream volume [ml-service/app/worker.py] — deferred, pre-existing: same queue-list-ordering pattern used since Story 1.2, not introduced uniquely by this story; worker-fairness/scaling is out of MVP scope.

### Architecture compliance (non-negotiable)

- **AD-1 (voice-first, no bypass, and transcript-failure isolation):** a transcript-stage failure must never fail the Call — `Call.status` is untouched by `run_transcript` in every code path, success or failure (Task 6). The acoustic signal (Story 1.3) remains independently valid regardless of this story's outcome.
- **AD-5 (STT engine lock):** faster-whisper is the only permitted engine; word-level timestamps are mandatory on every `TranscriptTurn`. Do not substitute or add a second STT engine.
- **AD-7 (consolidated ML/audio service, queue-only crossing):** `run_transcript` lives in `ml-service`, invoked only via RQ job (never a direct in-process call from `web-api` or from `run_acoustic`) — the enqueue in Task 7 is intra-service stage-chaining via the job queue (AD-13), not a function call.
- **AD-11 (one VAD boundary set, rolling context, no scalar `TranscriptTurn.segment_id`):** reuse the same `TimelineSegment` boundaries already established by ingest/VAD as the STT chunking unit (Task 5); the `TranscriptTurn`↔`TimelineSegment` relationship is many-to-many via time-range overlap only (Task 2) — this is the single most likely point of accidental architecture violation if the schema naively copies `AcousticEvidence`'s 1:1 `segment_id`-PK pattern.
- **AD-13 (RQ/Redis orchestration, worker-only status writes):** `run_transcript` never writes `Call.status`; only `run_ingest` and `run_acoustic` do (and only in their respective failure paths — `run_transcript` never fails the Call at all, per AD-1).
- **AD-14 (local-only inference):** faster-whisper model weights are pre-fetched at Docker build time (Task 8); no cloud STT call at request time.
- **AD-18 (CPU-only deployment):** `WHISPER_DEVICE="cpu"`, `WHISPER_COMPUTE_TYPE="int8"` — no GPU-specific code paths.

- **`faster-whisper` (`/systran/faster-whisper`) model init:** `WhisperModel(model_size_or_path, device="cpu", compute_type="int8", download_root=...)` — CTranslate2-backed, `download_root` sets the model cache dir (useful for the Docker build-time pre-fetch, Task 8).
- **`faster-whisper` transcription API:** `model.transcribe(audio, word_timestamps=True)` returns `(segments: Iterable[Segment], info: TranscriptionInfo)`. Accepts a file path, a numpy array, or a file-like object as `audio` — a torch tensor must be converted to numpy first. Transcription is **lazy**: iterate or `list(segments)` to force execution.
- **`Segment` object:** `.start`, `.end` (float seconds, relative to the audio passed in), `.text`, `.words` (list of `Word`, populated only when `word_timestamps=True`).
- **`Word` object:** `.start`, `.end` (float seconds), `.word` (string), `.probability` (float).
- **Consistency Convention (Architecture spine):** in-audio timestamps are float seconds relative to Call start — faster-whisper's native word-timestamp unit is explicitly named by the Architecture spine as the source of this convention; use the raw float-second values as-is (after offsetting back from a context-padded slice to Call-absolute time), no unit conversion needed.
