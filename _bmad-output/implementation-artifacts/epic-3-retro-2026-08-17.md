## What Went Well

- "Leave unattributed rather than guess" held as a consistent house principle across the epic (3.1's >2-channel gap, 3.2's `fill_nearest=False` decision).
- Epic 2's "build the contract, not the data" pre-built seams paid off substantially: `SpeakerLabel`, `TranscriptPanel`'s reason-line pattern, and the Dashboard/Call-row copy contracts were all consumed verbatim by 3.1–3.4 with zero new components or copy authored (3.4 AC6).
- pyannote Community-1's lack of native per-turn confidence (a paid precision-2-only feature, confirmed via Context7) was resolved with a word-level speaker-agreement-ratio heuristic, directly consistent with AD-6's own stated expectation that confidence should be lower for overlapping speech.
- Story 3.3 was a clean response-contract-only story — zero ml-service/DB/frontend changes, pure derived-flag-at-read-time, following Story 1.8's precedent exactly.

## What Was Challenging

- **No schema migration path** — every story (3.1, 3.2) hit the same "edit `CREATE TABLE IF NOT EXISTS` in place" limitation; a pre-existing local/Docker DB needs a full reset to pick up new columns. Known since Epic 1, still unowned.
- **Cascading breakage in out-of-scope test files** — `test_fusion_run.py`/`test_sentiment_run.py` call `db.persist_transcript_turns` with a fixed-shape tuple; grew 6→8 fields (3.1), then 8→10 (3.2), breaking both files each time (predicted and handled, not a surprise, but still a recurring tax).
- **Architecture-pinned `whisperx==3.8.6` proved uninstallable** alongside the project's `torch==2.13.0` pin — no whisperx release supports pyannote's Community-1 tier while also satisfying the torch constraint. Resolved via a user-approved deviation (drop whisperx, call `pyannote.audio.Pipeline` directly, skip forced re-alignment). See "Architecture Reconciliation" below.
- **Weak/misleading regression tests recurred across 3.1, 3.2, 3.3** — tests that would pass identically even if the behavior they claim to guard regressed.

## Architecture Reconciliation (significant discovery, resolved this retrospective)

`ARCHITECTURE-SPINE.md`'s AD-6 still described "WhisperX orchestrating... forced alignment" as the mono-diarization mechanism, and the Stack table still listed WhisperX 3.8.6 as an active dependency — but Story 3.2 had already dropped `whisperx` entirely from `ml-service/pyproject.toml` (a user-approved deviation, documented inline in `diarize.py`'s module docstring and the story's Dev Notes) without the canonical architecture document ever being updated to match. Two sources of truth disagreed silently.

**Resolved today:** `ARCHITECTURE-SPINE.md` AD-6 now carries an explicit "SUPERSEDED IN PART" record — the original rule text is preserved, followed by: what changed (direct `pyannote.audio.Pipeline` call, no forced re-alignment, `whisperx` removed as a dependency), what did not change (the pinned Community-1 model/tier — this AD's core "never the paid tier" prohibition is fully intact), and a capability-impact assessment. Checked against FR-16, AD-2, AD-5, AD-10, and NFR-1: none are violated by dropping forced re-alignment, since no FR/AC/UX document requires that specific refinement pass — AD-5 only requires word-level timestamps, which faster-whisper already provides directly. Any residual imprecision from skipping re-alignment is expected to surface as reduced word-agreement-ratio confidence, not silently-wrong high-confidence attribution. AD-10 and the Stack table's WhisperX row and source-tree comment were updated for consistency.

**Important distinction (Project Lead):** documenting the deviation does not restore the dropped capability. The record exists so this decision can be deliberately revisited in future work, not so it can be forgotten as "resolved."

## Key Insight

Architecture-pinned dependencies must be empirically verified installable together *before* a story starts building against them — Epic 1's "verify empirically, don't trust documentation" lesson applied to a single model checkpoint in Epic 1, but Epic 3 showed the same failure mode can happen at the whole-stack dependency-resolution level, not just a single artifact. The Epic 1 environment-validation action item is now considered to have failed in practice and is escalated to a mandatory gate.
