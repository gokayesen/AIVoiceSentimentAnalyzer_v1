## What Went Well

- Token-only CSS, BEM-lite naming, and a single `callsApi.ts` module owning every fetch (AD-7 boundary) — established in 2.1, held for all 7 stories with zero exceptions.
- The "stub extension-point" pattern (`onBreadcrumbClick`, `onSelectCall` built as no-op props early, wired later in 2.4) avoided a real refactor cost.
- The decision to skip `react-router-dom` (explicitly deferred by 2.1 and 2.3, finally resolved in 2.4) avoided a premature dependency.
- The "keep `SessionCallList` mounted-but-hidden, never unmounted" pattern (2.4) preserved client-only session state across navigation.

## What Was Challenging

- **Epic 1's API surface was repeatedly insufficient:** nearly every Epic 2 story that touched the backend had to add a "minimal correcting endpoint" it hadn't planned for (CORS middleware, `GET /calls/{id}`, `/transcript`, `/acoustic-summary`, timeline extensions).
- **The same nested-interactive-element / accessible-name bug class was caught independently in code review 3 times:** 2.2 (delete button inside clickable row), 2.3 (keyboard Enter triggering both handlers), 2.7 (a new `role="button"` addition bleeding a nested `<button>`'s label into the row's accessible name).
- **Accessibility work was systematically underestimated and deferred:** 7 items from Stories 2.3, 2.5, and 2.6 were explicitly punted to Story 2.7's cross-cutting pass.
- **`frontend/` was never committed to git during Epic 2**, which meant every `git diff`-based code review repeatedly misread pre-existing code as new/duplicate/missing (dozens of findings per story dismissed as diff-construction artifacts) — resolved today by committing the full Epic 2 + Epic 3 codebase.
- **No real browser validation exists anywhere in this project.** Story 2.7 disclosed that 3 of its 8 tasks (focus-ring, text-scaling, responsive breakpoints) have no automated-test equivalent at all, since jsdom cannot compute real CSS/layout. This is the epic's most significant open finding — flagged as high-priority by the Project Lead.

## Key Insight

"174 tests passing" is not the same claim as "verified in a real browser." The project has no mechanism today to validate CSS-dependent behaviors (focus-ring, text-scaling, responsive layout) beyond jsdom's approximation. Epic 3's own UI story (3.4) was checked directly and confirmed **not** to depend on any of these unvalidated behaviors — it reused Epic 2's components verbatim with no new CSS/layout surface — so the gap did not bite this time, but it remains open project-wide.

## Story 2.7 Close-Out Accuracy Check

Of the 7 accessibility items explicitly assigned to Story 2.7 from Stories 2.3/2.5/2.6: 5 were fully closed, 1 was half-closed (`CallRow`'s `role="button"` half closed; the `aria-live` state-transition half deliberately left open as a new-feature ask, out of a verification-pass story's scope), 1 was left open by design (duplicate-filename accessible names — needs a product/UX decision no story has authority to make alone). Story 2.7's own Dev Notes state both open items "should be re-logged in `deferred-work.md`" — this did not actually happen at the time. Re-logged now as part of this retrospective (see `deferred-work.md`, "Deferred from: Epic 2 retrospective"), along with a third cross-story gap found during this review: Story 2.3's AC2 (Dashboard delete action), deferred from 2.3 to 2.4 and never picked up by any story since.

**Correction to initial synthesis:** an earlier pass flagged "`single_modality_flag` never surfaced in the Dashboard" as an open gap. Verified false — Story 2.6 closed this at the Call level. No per-segment equivalent exists in the API contract to begin with, so this is not an unclosed UI task.
