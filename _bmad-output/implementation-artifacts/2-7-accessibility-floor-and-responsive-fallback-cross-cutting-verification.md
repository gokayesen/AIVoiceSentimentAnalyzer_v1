# Story 2.7: Accessibility Floor & Responsive Fallback (cross-cutting verification)

Status: done

<!-- Note: Validation is optional. Run validate-create-story for quality check before dev-story. -->

## Story

As an Analyst,
I want the entire console to remain fully usable by keyboard, at larger text sizes, and on a narrower browser window,
so that the tool works reliably regardless of how I access it.

## Acceptance Criteria

1. **Given** every focusable element built across Stories 2.1–2.6, **When** focused, **Then** each shows the `focus-ring` treatment — verified app-wide, not per-component in isolation. **See Dev Notes "Focus-ring audit result"**: 15 candidate elements were audited; 4 are correctly non-focusable by design (hidden file input, the drag-drop container, the dialog-overlay click shortcut, transcript turns with no overlapping segment), leaving 11 genuinely focusable elements — 10 already have a `:focus-visible` rule matching `DESIGN.md`'s two-variant (`--color-focus-ring` / `--color-focus-ring-on-chrome`) spec. One real gap was found (`analysis-dashboard__back-button`, the error-state "Back to Session Call List" button) and is fixed by this story.
2. **Given** every Interaction Primitive defined across Epic 2, **When** attempted via keyboard only, **Then** each completes successfully end-to-end with no mouse-only step. **See Dev Notes "Keyboard-completeness audit result"**: audited, no functional gap found — every primitive (upload via file picker, timeline segment select via click/arrows, call-row/transcript-turn select via Enter/Space, delete-a-Call via icon-button + `ConfirmDialog`, breadcrumb return-to-list) already has a full keyboard path. One semantic (not functional) gap closed as part of this story's verification pass: `CallRow`'s complete-row lacked `role="button"`, inconsistent with the `role="button"` pattern already established on `Timeline`'s and `TranscriptPanel`'s own interactive elements.
3. **Given** the transcript panel and Session Call List, **When** text is resized up to 200% (per the WCAG 1.4.4 benchmark), **Then** no content or functionality is lost and no text overlaps — stated as a requirement outcome, independent of which specific resizing mechanism (OS-level, browser zoom, or otherwise) is used to verify it. **See Dev Notes "Text-scaling audit result"**: two fixed-width/height text-bearing containers found and hardened (`transcript-panel__time`, `timeline__track`); one (`confirm-dialog`) audited and confirmed safe as-is (already has `max-width: 100%`, a hard `width` there only affects internal text wrap, not clipping/overlap).
4. **Given** a viewport narrower than ~960px, **When** the Dashboard renders, **Then** its two-column grid stacks to a single column, transcript first.
5. **Given** a viewport narrower than ~960px, **When** the summary row renders, **Then** it wraps to a 2×2 grid.
6. **Given** a viewport narrower than ~960px, **When** the Session Call List renders, **Then** the delete `icon-button` becomes always-visible rather than hover-only.
7. **Given** this fallback, **When** compared to a dedicated mobile/tablet layout, **Then** no such layout is implemented — narrower-desktop-window fallback only, not a touch-first redesign.
8. **And** this story introduces no new accessibility requirement beyond what Stories 2.1–2.6 already committed to — verification pass plus the responsive-fallback behavior itself. **See Dev Notes "Accessibility-floor debt closed by this story"**: five items were explicitly deferred to "Story 2.7" **by name** across three prior stories' code reviews (2.3, 2.5, 2.6) — not new requirements invented here, but real shortfalls against what Stories 2.1–2.6's own Interaction Primitives / Accessibility Floor commitments (`EXPERIENCE.md`) already required and didn't fully deliver. This story closes all five (one of the five — the always-visible delete affordance — is satisfied by Task 7's own responsive-fallback work, not a separate fix). A sixth deferred item (`CallRow`'s state-transition `aria-live`) is only half-closed — its `role="button"` half is fixed, its live-announcement half is explicitly left open as a genuinely new feature, not a verification-pass fix. A seventh item (ambiguous accessible names when two Call rows share a filename) is left fully deferred — it requires a UX decision not specified anywhere in `DESIGN.md`/`EXPERIENCE.md`, which this story does not have the authority to invent unilaterally.

**Traceability:** UX-DR16, UX-DR17; AC8's closed items trace to `deferred-work.md`'s "code review of 2-3-delete-a-call-ui-only", "code review of story-2-5", and "code review of story-2-6" sections (see Dev Notes "Accessibility-floor debt closed by this story" for the exact provenance of each).

**Dependency:** Stories 2.1–2.6 (all of Epic 2's UI built so far) — this is a cross-cutting verification pass over all of it, plus the one net-new responsive-fallback implementation (AC4–AC7). No dependency on Epic 3 (still `backlog`).

A codebase-wide grep for hardcoded `width`/`height`/`max-width`/`max-height` in px found exactly 3 text-bearing elements (decorative-only fixed sizes — `badge-dot` 7×7px, `icon-button` 22×22px and its 14×14px SVG — are not a risk, since none contain text): `transcript-panel__time` (42px width holding the turn timestamp text), `timeline__track` (36px height + `overflow: hidden`, holding the per-segment glyph text), and `confirm-dialog` (300px width holding the dialog's title/body/warning/button text).
